# OneGodian Improvement Evaluation

## Fix the comparison
Read the candidate diff and raw evidence. Record baseline/candidate revisions or hashes, evaluation version, environment, inputs, commands, timestamps, and exit codes. Reconcile installed and repository versions before runtime claims.
Define success metrics and non-negotiable regressions before evaluation. Compare equal task sets and resource budgets. Repeat stochastic trials sufficiently to expose variance; disclose sample sizes and uncertainty. One success does not prove general improvement.

## Protect evaluation integrity
Keep held-out cases and acceptance policy outside candidate write access. Do not reveal hidden answers to the candidate. Model agreement and agent critiques are supporting analysis, not factual verification. Prefer executable checks and an independently controlled evaluator. If unavailable, label review self-assessed and leave promotion unresolved.
Never change expected values just to match candidate output. Establish the authoritative contract first and review legitimate test corrections separately. Retain negative results.

## Select relevant regressions
For WordPress, inspect actual code and release requirements. Check canonical routes/page IDs, shortcode registration/rendering, capabilities, ownership, nonces, private-data exposure, and relevant BuddyPress/WooCommerce integration. Establish Belief Mapper ownership from current evidence. Prefer plugin-scoped CSS; inspect real mobile overflow, navigation, focus, and long labels.
For bridges/APIs, check authentication, authorization, secret redaction, error semantics, routing, and health/readiness contracts. Do not expose credentials.
Use checks proportional to changed contracts. Separate syntax/unit results from staging browser, installed-plugin, integration, and production checks.

## Decide
Return PASS only when predefined gains and required regressions are evidenced; FAIL for demonstrated breaches; INCONCLUSIVE for missing or incompatible evidence. Repository tests do not establish deployment. Security/privacy failures block promotion regardless of gains.
Report criterion, baseline, candidate, evidence, and result; identify staging-only checks and disposition. Hand off for independent evaluation and authorized release review; never self-promote.
